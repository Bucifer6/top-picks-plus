# Store

## Responsible for
The plugin's own files in the plugin data folder `<programdata>\data\TopPicksPlus\` (D23, data.md): managed.json, plays.json, run.json, run.previous.json and state.json (D29). Every write is atomic and created new (spec "Words used here", D56): write a temp file created new, then move it over the live file with `File.Move` and overwrite (or into place); leftover temp files at the top level of the data folder are removed at start-up. A data file that is a link or a folder is never read: it is removed and counts as missing, setting its pending flag (plays.json, state.json). One lock around every change to plays.json, and the roll-up (F6, D33); one lock around every change to managed.json; one lock around every change to state.json (spec "Pending flags"). Checking every field against data.md's rules when reading, and handling damaged files as spec F9 says (D37: managed.json refuses runs, state.json reset, run.json renamed aside, plays.json deleted at once). Emptying `staging\` (F4 step 6). Making and pruning `backups\` (plays.json with `"today": []`, TopPicksPlus.xml copied as bytes into a file created new, never parsed). Copying run.json to run.previous.json only when it was successful (D41). Carrying the pending flags as spec "Pending flags" says. Removing leftover `*.tmp` files when the root entry point asks at start-up. Saying whether the plugin data folder is a link (reparse-point attribute, F9). A file that can't be opened is an error, never "damaged" (spec F9).

## Belongs here
File reading and writing for those files, staging and backups, behind the `IStore` interface Run uses (so Run can be tested with a fake). Missing and damaged files follow spec F9 exactly; never a crash. Its own deletes stay inside the plugin data folder with full-path and no-link checks (reparse-point attribute; no link on the way to `staging\`, `backups\` or the file; a link inside staging or a backup folder is removed as a link, never entered). Every action on a found entry uses its exact path (`\\?\` form, spec "Words used here"), with ReadOnly cleared before a delete or replace; wrong-kind entries at its own fixed names (a folder called `state.json.tmp`, a file called `staging`) are removed first; a backup folder, or a file at this minute's backup folder name, that is a link is removed as a link. Replacing writes use `File.Move` with overwrite, never `File.Replace` (D57); a failed write, move or delete is tried once more after 2 seconds. A failed write deletes its own `.tmp` at once, C76. Paths come in as Logic's plain paths record.

## Does not belong
Plugin settings (Settings). Deciding anything (Logic; the roll-up's sums are Logic functions). Writing or reading copies in the Top Picks folder (Run). Interpreting the settings file (Settings, EmbyBridge).

## May use
Logic (its record types and field rules), plain .NET file access, System.Text.Json (compiled against, not shipped, D30).

## Must not use
Artwork, EmbyBridge, Run, Settings, any `MediaBrowser.*` or `Emby.*` type, SkiaSharp, `System.Net`, `System.Diagnostics.Process`, the root namespace, any file outside the plugin data folder except copying TopPicksPlus.xml into backups.
