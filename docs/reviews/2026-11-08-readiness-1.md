# Top Picks Plus – Stage 5 readiness review (reviewer 1, 2026-11-08)

Scope: CLAUDE.md, docs/spec.md (v3), data.md, checks.md (C1–C50), decisions.md (D1–D42), every README under src/ and tests/, both .csproj files, Boundaries/*.cs, build.yml, the logbook (0001–0005) and both reviews. docs/handover/ was not read. No files were changed.

Overall: these docs are much better than most at this stage. The run order, the resume rules, the delete safety and the takeover are written carefully. What's weak: about a third of the safety checks are marked "Automatic" but have nowhere to run. Nothing says what happens when a run crashes without Emby restarting. Several things a builder will meet on a real TV library (specials, double episodes, which kind of Emby ID) are not decided.

---

## 1. Restatement (plain English)

Top Picks Plus replaces the old Top Picks plugin. It keeps the same "Latest Top Picks" row on everyone's Emby home screen, but this time the row is numbered 1–10 in the right order every week.

- **Every Sunday at 05:00** (UK time), or when you press Run now, it picks 10 titles. Any pins you have set go first, in your order. The rest are the titles the most people watched over the previous Sunday to Saturday. A "viewer-day" is one person watching a title on one day, so a binge counts once per person per day. If too little was watched, the gaps go to the newest additions.
- **Counting plays:** all week it notes every time someone stops playing something. A play counts if Emby marks it watched, or if the person has watched 50% of it that day (20 minutes if the length isn't known). For a series this is per episode. It keeps 90 days of this, on the server only, and only administrators can see it.
- **What it does to your files:** for each pick it builds a folder in `programdata\data\top-picks`. The folder holds small "pointer" files (.strm) to your real videos on N:\ and K:\, information files (.nfo), subtitles, the logo and backdrop, and a numbered picture (1000×562, big white number on the left). Your real media files are never changed. Copies are built in a hidden staging folder first. Then titles that dropped out are deleted, staying titles are updated in place (so your watched ticks stay), and new titles are moved in.
- **Getting the order right:** after a rescan of only the Top Picks library, it sets each copy's "date added" inside Emby, one hour apart (pick 1 newest). It refreshes the pictures, then checks the row the way a normal user sees it. After every library scan and every restart it checks the dates again and puts back any that Emby changed.
- **Watched status:** finishing or stopping a copy updates the real title's watched tick or resume point. A new copy starts with your existing ticks.
- **What you see and control:** Dashboard → Plugins → Top Picks Plus. There you choose libraries, pick the user the row check looks through, search for and drag pins, press Run now, and read a report: each pick's rank and reason, whether the row check passed, missing pins, artwork failures and the last refused run.
- **Taking over from the old plugin:** you uninstall the old plugin first. If it is still loaded, Top Picks Plus does nothing at all. On its first run it adopts every folder in top-picks that holds both a .strm and an .nfo, and then deletes them or replaces them with fresh copies. Anything else in that folder is left alone forever. The first week's counts come from Playback Reporting's history, or from Emby's "last played" dates if that can't be read.
- **When things go wrong:** if Emby restarts mid-run, the run carries on with the same picks (at most 3 tries, then it is marked failed). If the rescan takes too long, the run is marked "incomplete" and the date checker finishes the order later. A damaged list of managed folders means it refuses to run and deletes nothing. A damaged play log or run record is renamed and started again. A missing Top Picks library means it refuses. It never deletes a folder that isn't on its own list or that sits outside top-picks, and it never follows links.

## 3. Builder readiness

**Features or rules with no check (or only a partial one):**
- F3 folder-naming rules (forbidden characters, trailing dots/spaces, no year, ` - 2`/` - 3`, reserved names → `_`): the Logic README promises tests, but there is no C-number. C50 covers only one clash case.
- D30 .nfo contents and XML escaping (a title with `&` or `<`), and the field lists: no check. If the age rating is missing from the .nfo, F9 quietly breaks.
- The rank-date sum (pick n = rank time − (n−1) h, cut to the whole minute): only manual (C2). It should be an automatic Logic check.
- D41 (no missed run after first install): no check.
- F6 20-minute rule when the length is unknown, "marked played counts on its own", and D29 limits (never below 0 or above the runtime; start not seen = 0): no checks. C12 covers only 50% and 5 minutes.
- F5 "unranked copies skipped", and whether the guard covers episodes: no check.
- D20 fallback to the first administrator when no unrestricted user exists: no check.
- F9 personal data (play log never leaves the folder): not testable. Accept that in writing.

**Checks that can't fail, or can't be automated, as written:**
- C36, C45, C47, C49, C50 and C43: see guess #1. They are marked automatic, but under D18 and the READMEs they have no home. C45 and C49 can't make junctions on the Linux CI. Fix: either (a) a decision that the file-operation executor (delete containment, swap, staging, resume) lives in Storage, or in an Emby-free class in EmbyLink, with temp-folder tests; plus a `windows-latest` CI job for the junction cases (or symlinks on Linux with that limit written down); or (b) re-label them as manual and give the owner a recipe. Option (a) is the right one for safety rules.
- C43 also needs SkiaSharp's native library on the CI machine. Artwork excludes runtime assets and there is no Artwork test folder or decision.
- C26, C28, C29: see guess #14.
- C21 and C4 can pass by luck (a restart between steps that happen to be safe). They are fine as smoke tests, as long as C36 is real.

**Contradictions:**
- D18 / EmbyLink README ("tested by owner only") vs checks.md labelling EmbyLink-side safety checks "Automatic".
- D25 fallback "counts as one viewer-day" vs the stored row (minutes 0) under F6's rules.
- Spec F4 step 4 says the .nfo date means "a later refresh can't undo it" (only true if the format and time zone match how Emby reads it; not specified).
- Spec F9 "nothing not on the managed list is ever touched" vs staging deletes (D35).
- The spec says the first run *imports* last week; D41 means plays are already being logged by then (double count, #4).

**Scaffold rules vs the plan:**
- The walls themselves fit the plan, but they leave the swap, resume and delete code with no automatically testable home (above). Settling this needs an owner-approved decision: a new arrow, or moving the file executor into Storage. The READMEs say a new arrow needs the owner.
- tests/README lists only Logic and Storage tests. If any automatic Artwork or file-operation tests are wanted, the README and possibly the folder plan need updating.
- Stryker is owed by "the first Logic chunk", with no threshold number given.
- No build-chunk order or phased release plan is written down. The play listener should probably ship first so data builds up. That may be part of Stage 5's own output, but it isn't in the docs yet.

## 4. Confidence: 72 / 100

The core is well specified, and the past reviews show the hard parts were worked through: the run order, crash safety in the swap, delete containment, takeover, fixed lists for reasons and refusals, and the exact versions and IDs. A builder could write Logic and Storage today with little guessing.

The score is held down by four things:
- (1) The most important safety checks are marked automatic but have no place to run under the current walls and Linux CI.
- (2) A run that crashes without a restart has no defined outcome, and the obvious way to build it can leave the order guard switched off.
- (3) Real-library edge cases (episode naming, which ID, what can be pinned, the .nfo date format) will make the builder invent behaviour.
- (4) A few checks the owner simply can't run on a single home server.

To get above 90:
- a decision on where the file-operation code lives, with temp-folder and Windows CI tests for C36/C45/C47/C49/C50;
- a decision on in-run failure, the lock and the row-check outcome;
- decisions on ID type, what can be pinned (and the cap), episode and special naming plus file-name cleaning, the .nfo date format, the import cut-off, and guard coverage of episodes;
- a reference artwork image with measurements, and the Top Picks library setup requirements;
- automatic checks for the naming, .nfo, rank-date, D29 and D41 rules;
- runnable recipes or test switches for C26/C28/C29;
- the spec branch merged.
