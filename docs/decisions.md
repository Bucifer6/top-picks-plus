**Spec gaps settled 2026-11-08 (second job).** D20–D23 are the owner's answers to Q1–Q4. D24–D41 were decided by Claude; D42 by the owner (owner delegated the technical gaps), using facts read from the owner's Emby 4.10.2 system folder.

| D20 | 2026-11-08 | **Row-check user:** a setting picks the user the row check looks through. Empty = the first user (in Emby's user list order) who is not an administrator and has no parental-control limit and no blocked libraries; if there is none, the first administrator, and the report says so. The check passes if the row holds exactly the copies that user is allowed to see, in rank order (1–10 for an unrestricted user). **How "allowed to see" is worked out:** a normal item query on the Top Picks library as that user, with the same played/unplayed filter the Latest request uses, sorted by rank; the Latest row Emby returns must equal that list. So titles hidden because the user watched them or is blocked from them don't fail the check | Owner's choice (Q1); "how" by Claude after the review |
| D21 | 2026-11-08 | **The 7 days:** the 7 full UK calendar days before the day the run starts. For the Sunday 05:00 run that is the previous Sunday to Saturday; a mid-week Run now uses the 7 days before that day. Plays older than the 90 full UK days before the run day are removed; the run day's own plays are kept | Owner's choice (Q2) |
| D22 | 2026-11-08 | **Series 50% rule is per episode:** sittings of the same episode on the same day add up; minutes from different episodes don't. Marked played on any episode still counts | Owner's choice (Q3) |
| D23 | 2026-11-08 | **Pins don't have to be in the chosen libraries.** A pin is used if its source title still exists and its file can be found; the library choice only limits the automatic picks and filler | Owner's choice (Q4) |
| D24 | 2026-11-08 | **JSON library: System.Text.Json, compiled against but not shipped.** Emby 4.10.2 runs on .NET 8.0.32 (EmbyServer.runtimeconfig.json), whose shared framework always includes System.Text.Json 8. The plugin references the System.Text.Json package **8.0.6**, pinned exactly (never 9 or later; a newer 8.0.x patch only if the audit flags 8.0.6) with runtime assets excluded; only Storage uses it. Emby's own IJsonSerializer is not used because Storage must not use the Emby SDK | Keeps the one-DLL rule (D17) with no clash, like SkiaSharp (D15) |
| D25 | 2026-11-08 | **Playback Reporting import (F6, once).** Its history is `programdata\data\playback_reporting.db`, table `PlaybackActivity` (DateCreated, UserId, ItemId, ItemType, PlayDuration in seconds). EmbyLink opens it read-only through the SQLite library Emby already loads (SQLitePCL.pretty 1.2.2 on Emby's own SQLitePCLRawEx); the NuGet SQLite packages are not used (they need assemblies Emby doesn't have). **Compile reference:** the import chunk first checks whether the pinned Emby SDK package (D14) restored in CI provides SQLitePCL.pretty; if it does, EmbyLink compiles against it, not shipped. If it doesn't, there is no direct read: no Emby DLLs are copied into the repo and no reflection tricks are used, and the import uses only the fallback below. Rows: Movie → that movie; Episode → its series, keeping the episode; other types ignored; minutes = PlayDuration ÷ 60; marked played = false. The import chunk first proves on the owner's server that the file can be read and whether DateCreated is UTC or local, against a known play. **If it can't be read**, the first week is seeded from Emby's own per-user "last played" date instead: each user's item last played inside the 7 days counts as one viewer-day on that day. Imported rows use the movie's or episode's runtime from Emby as `runtimeMinutes`. Fallback rows go into plays.json with minutes 0 and `markedPlayed` = the user's played flag on that item in Emby. `PlaybackReportingImported` is set true after either path, so it is tried once only. The report says which source was used | No extra DLL; a fallback better than "recently added only" |
| D26 | 2026-11-08 | **Safe run and resume.** A run fixes its 10 picks and its rank time when it starts; a resume never re-chooses. run.json is saved (atomically) at every step change. Swap order: (1) drop-outs: entry marked `leaving` in managed.json, folder deleted, entry removed; (2) staying copies rewritten in place, one file at a time (temp file then rename); (3) new copies: entry added as `incoming` to managed.json **before** the folder is moved in from staging, then marked `active`. So a folder in top-picks is always on the managed list before it exists there. Staging is emptied only when a new run starts, never on resume. **On resume** each step is simply done again: `leaving` → delete if still there and remove; `incoming` → move from staging if still there, re-prepare if staging lost it; rescan, dates, artwork and check run again. A resume that fails 3 times marks the run `failed` and the report says so. **The order guard (F5) is paused while a run is `running`**; the run sets dates itself | Every step can be repeated safely; nothing is ever orphaned or deleted unmanaged |
| D27 | 2026-11-08 | **Rank time** = the run's start time in UTC, cut down to the whole minute, stored in run.json and kept by a resume. Pick n's rank date = rank time − (n−1) hours. Written to managed.json at the swap and into each .nfo at prepare | One fixed value; the guard and resume agree |
| D28 | 2026-11-08 | **Linking copies to source items.** managed.json lists every video file in each copy (`items`: copy file path → source item ID). A play or watched mark on a copy is looked up by the copy file's path, which stays the same across rescans (item IDs may not). **Old-plugin folders at takeover:** the folder's .strm (for a series, its first episode .strm) holds the real file path; the source is the Emby item with that path (case-insensitive), an episode's series for a series. If no item matches, the folder is still adopted (so it can be removed) with no source and is deleted at the first run. **Adopted folders are never updated in place:** if one is still a pick, it is replaced by a fresh copy, so no old files are left behind | Paths are stable; takeover cleans up fully once |
| D29 | 2026-11-08 | **Minutes watched** = stop position − start position, from Emby's playback-start and playback-stopped events (matched by session and item), never below 0 or above the runtime. If the start wasn't seen (e.g. Emby restarted mid-play), minutes = 0 and only "marked played" can count | Uses only Emby's own events |
| D30 | 2026-11-08 | **Copy files.** Logic builds the text of every .strm and .nfo (XML-escaped); EmbyLink writes them. Movie .nfo: title, originaltitle, year, plot, mpaa (age rating), genres, premiered, runtime, provider IDs, dateadded. tvshow.nfo: the same for the series. Episode .nfo: title, season, episode, plot, aired, runtime, mpaa, dateadded. Episode files are named `Series - SxxEyy - Episode title`; subtitles are copied for episodes too. A staying copy keeps its folder name even if the title is renamed. A name clash with any existing folder (managed or not) gets ` - 2`, ` - 3`. Windows reserved names (CON, PRN, AUX, NUL, COM1–9, LPT1–9) get `_` added. In a staying series, new episodes are added and episode files the plugin wrote last time that are no longer available are deleted; files not on the copy's `items`/file list are never touched | Builder needs exact contents; nothing unmanaged is ever removed |
| D31 | 2026-11-08 | **Run report fields and refusals.** Pick reasons are a fixed list: `pinned`, `viewerDays`, `filler`. The report also holds missing pins, per-pick `artworkFailed`, plays recorded in the 7 days, the seeding source (D25) and resume count. Refusal reasons are a fixed list: `alreadyRunning`, `oldPluginLoaded`, `libraryMissing`, `dataDamaged`; a refusal is saved as `lastRefusal` (time, reason) and never overwrites the current or last run. **One source of truth:** `lastSuccessfulRunUtc` lives in run.json (removed from Settings); a run counts as successful if it finished or ended incomplete | Fixed lists can be tested; a refused Run now can't wipe a running report |
| D32 | 2026-11-08 | **Damaged data files.** managed.json unreadable → every run refuses (`dataDamaged`) and nothing is deleted. plays.json unreadable → renamed to `plays.damaged-YYYY-MM-DD.json` (` - 2` etc. if that name exists), a new empty log is started, and the report says so. run.json unreadable → renamed the same way and treated as "no unfinished run" | Never delete on bad data; losing counts beats stopping |
| D33 | 2026-11-08 | **Old-plugin guard** matches exactly: assembly name `Emby.TopPicks` or plugin ID `672630FC-6FB8-4207-9C7B-AB414CD85B53` (read from the installed Emby.TopPicks.dll 1.0.0.63). **This plugin's fixed ID: `744d00f2-735f-4d57-a952-47e98a5b6f0d`**, never changed | Can never block Top Picks Plus itself |
| D34 | 2026-11-08 | **SkiaSharp 2.88.3** exactly (the version in Emby 4.10.2's system folder), runtime assets excluded. Number font: **Oswald Bold** (SIL OFL 1.1), embedded, with its licence file in `src/TopPicksPlus/Artwork/` | Matches what Emby loads; open licence |
| D35 | 2026-11-08 | **Small rules.** Final tie-break: source item ID compared as a number (Emby IDs are digits), lowest first, so the order is always fixed. Start-up order: (1) if the old plugin is loaded, do nothing else and report it; (2) else resume an unfinished run if there is one; (3) else the order guard at 2 minutes; (4) the missed-run rule at 10 minutes, skipped if a resume ran. Top Picks folder = Emby's data path + `top-picks`, compared with library folders case-insensitively. Plugin data folder = `programdata\plugins\TopPicksPlus\`; staging inside it is the only place outside top-picks the plugin ever deletes from | Removes guesses a builder would otherwise make |
| D36 | 2026-11-08 | **Storage gets its own automatic tests** in `tests/TopPicksPlus.Tests/Storage` (atomic save, missing file = empty, damaged file reported and renamed, managed.json refusal), using temporary folders | Storage rules are safety rules (D32) and can be tested without Emby |
| D37 | 2026-11-08 | **Delete containment (review Blocker).** Before deleting a folder, the plugin checks that its name is not empty, `.` or `..`, has no path separators, resolves to a **direct child** of the Top Picks folder (or of staging), and is not a junction, symlink or other reparse point. If any check fails, nothing is deleted and the report names the entry. Before staging is emptied, the staging folder itself must be a direct child of the plugin data folder and not a reparse point. A recursive delete never follows links: a junction or symlink inside a folder is removed as a link, and its target is never touched. A drop-out deletes its whole folder, including anything inside it; this is what "deletes only what it made" means for folders on the managed list | Stops a bad entry from deleting top-picks itself or anything outside it |
| D38 | 2026-11-08 | **Takeover rule (review Blocker):** a folder in top-picks is the old plugin's if it, **including its subfolders**, holds at least one .strm and at least one .nfo. Takeover runs once, at the start of the first run that passes the guards; a refused run leaves `TakeoverDone` false. Takeover **skips folders already on the managed list**, saves managed.json **before** setting `TakeoverDone`, and saving the settings page never overwrites `TakeoverDone` or `PlaybackReportingImported` (only the plugin sets them) | Old series folders keep their .strm files in Season folders |
| D39 | 2026-11-08 | **Leftovers from an earlier run.** Before preparing, a new run finishes old `leaving` entries (delete if there, remove entry) and turns old `incoming` entries whose folder is in top-picks into unranked `active` copies, which then drop out normally; `incoming` entries with no folder are removed. A **failed resume** is one that throws or stops without reaching `done`; `resumeCount` goes up at the start of each resume. At most 3 resumes are tried: at start-up, if `resumeCount` is already 3, no resume is tried and the run is marked `failed` | Nothing left half-done blocks or orphans later runs |
| D40 | 2026-11-08 | **File-level safety in staying copies.** Every copy (staying ones too) is first built in staging. Before a new file is written into a staying copy, it is added to that copy's `items`/`files` and managed.json is saved; only then is the file written. **Adopted folders still a pick** are handled as a drop-out followed by a new copy. When names are chosen at prepare, folders that are about to drop out (adopted ones included) don't count as clashes, so the new copy gets the plain name. If D37 refuses to delete such a folder, the new copy is moved in under the next free ` - N` name, never onto or into the folder that is still there. Watched ticks come back from the source (F7); resume points on the old copy are lost once, which is accepted | A crash can never leave a file the plugin can't later remove |
| D41 | 2026-11-08 | **First install:** with no `lastSuccessfulRunUtc`, the missed-run rule does not fire; the first run is the next Sunday 05:00 or Run now | No surprise run minutes after installing |
| D42 | 2026-11-08 | **Library-level blocks are not applied to copies** (accepted by the owner). A user blocked from a whole library still sees that library's titles in the Top Picks row; age-rating controls still apply to copies. Same as the old plugin | Owner's choice after the review |
