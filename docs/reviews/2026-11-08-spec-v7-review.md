# Spec v7 re-review, 2026-11-08

Reviewers: **Comp** (2 Blocker, 13 Should, 10 Nit), **Build** (0 Blocker, 13 Should, 8 Nit), **Sec** (0 Blocker, 13 Should, 8 Nit). Run at the same time on commit 20588d0. Stage 4 **not passed**; pull request 1 stays unmerged.

Comp confirmed v6 Blocker 2 is fixed and Blockers 1 and 3 are fixed in principle. Build found every feature buildable inside the walls. Sec found watched state, personal data and admin-only access soundly designed.

## Blockers
1. **Links inside a managed folder vs the new "check everything first" rule (Comp 1; also Sec 4).** v7 skips a whole operation if any check fails, and check 4 fails on any link, but F9 and C27 say a link inside a managed folder is removed as a link. Read literally, a copy with a junction inside is skipped and stays `stale` forever. Fix: a link *inside* the operation's folder passes the pre-check and is unlinked, never entered (walk the folder yourself, non-recursive delete of the link); only a link *on the way to* the folder fails.
2. **A half-updated series can sort into the row (Comp 2).** New episode files written before an update failed become new Emby items that read this week's `dateadded` from their .nfo; if Latest orders series by newest episode, the stale series lands among the picks. Needs a rule, e.g. the order guard sets every item of a stale copy to one fixed old date, or the update writes .nfo files in an order that can't leave new dates behind.

## Lesson
v7's one-line safety rule ("check everything before the first change") silently contradicted two older rules (links inside folders, adds not yet on the managed list). R1 asked to cross-check, but the cross-check looked at the new rule's own words, not at every rule it now *runs before* (card 0005, seen 4). And D43 proved film deletion, not episode deletion (card 0008, seen 3).
