# Storage – the plugin's own files

**Responsible for:** reading and writing `managed.json`, `plays.json`, `run.json` and `state.json` (the plugin's own flags `takeoverDone`, `playbackReportingImported`, `listeningSinceUtc`, D93) in `programdata\plugins\TopPicksPlus\`, and **every file change in the Top Picks folder and staging** (D43): writing copy files into staging, emptying staging, moving folders in, rewriting files in staying copies, and deleting folders and files only after the D37 checks (folders) and D82 checks (every path in `items`/`files`: inside the copy, no reparse points), never following junctions or links. It carries out the swap and resume steps that Logic plans (D26, D39, D40). Every JSON write is atomic: write a temp file, then rename over the old one.

**Belongs here:** file shapes matching docs/data.md, including the report fields in D81, the play `origin` and the import marker (imported rows and marker written in one save, then state.json, D80, D93); takeover saving managed.json before state.json (D38); a damaged state.json renamed to `state.json.damaged-<UTC time>` and rebuilt from the other files, refusing (`stateDamaged`) only when managed.json or plays.json is also unreadable (D95, C98); a refusal writing only `lastRefusal` and leaving the run's other fields unchanged (D94); mapping Logic's records to those shapes (D88); "data newer" stopping every write to all four files, `lastRefusal` included (D85, D93, D94); safe load (a missing file means empty; a damaged file is reported, never silently replaced), atomic save.
**Does not belong:** deciding anything (that's Logic), the owner's plugin settings (LibraryIds, Pins, RowCheckUserId: Emby keeps those in `plugins\configurations\TopPicksPlus.xml` via the project root; the plugin's own flags are not there, D93), talking to Emby (rescans, dates, events: EmbyLink).
**May use:** Logic (for its record types), .NET.
**Must not use:** Emby SDK, SkiaSharp, Artwork, EmbyLink, Settings, project root.
**JSON:** System.Text.Json, compiled against but not shipped (D24). **Damaged files:** D32. **Tests:** tests/TopPicksPlus.Tests/Storage (D36, D43), with temporary folders; junction tests run on the Windows CI job.
**Data:** play log holds user IDs and viewing days; it never leaves this folder (F9).
**Files (chunk 2):** `Records.cs` (file shapes: `PluginState`, `RunRecord` and its parts, `PlayLog`, `ImportMarker`, `FileStatus`, `LoadResult`), `Json.cs` (serializer settings and the managed/plays file shapes mapped to Logic's records, D88, D117), `SafePaths.cs` (atomic writes, reparse-point checks, link-safe deletes, D24, D37, D82), `DataFolder.cs` (the four files: safe loads, the "data newer" gate in front of every write, read-modify-write under one lock per folder, refusals writing only `lastRefusal`, damaged files set aside, state.json rebuild, import step, D32, D85, D93–D96, D118, D120, D121), `CopyFolders.cs` (top-picks and staging: listing, staging writes, emptying staging, carrying out Logic's swap/leftovers/staying-file plans, takeover; every delete after D37/D82 and the exact-name check D119; new copies carry their files, D124).
**Rules added in chunk 2:** an existing name must be listed under exactly that name (D119, so a Windows short name is refused); only folders on a readable managed list, and only files on an entry, are ever deleted; with any file newer, nothing in the four files, top-picks or staging is touched (D85), and a data file that can't be opened stops writes too (D128); the recursive delete re-checks its folder for a link at the last moment, and a new copy never takes over an unlisted folder (D126); the state.json rebuild is one replace (D127).
