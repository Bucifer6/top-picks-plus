## 1. Restatement (for the owner to confirm)

**What it is.** A plugin for your Emby server that replaces the old "Top Picks" plugin. Once a week it fills the "Latest Top Picks" row on the home screen with 10 titles, each with a picture showing a big number 1–10, and makes sure the row shows them in the order 1 to 10 left to right every time. You never have to do anything by hand; you can pin titles if you want.

**When it runs.** Every Sunday at 05:00 server time (UK time, following the clock changes), or when you press "Run now" (in Emby's Scheduled Tasks or on the plugin's own page). Only one run can happen at once; pressing Run now during a run is turned down with "a run is already in progress". If Emby was off and the last good run was over 7 days ago, it runs once 10 minutes after Emby starts (but not on the very first start after installing).

**How it picks the 10.**
1. Your pins first (optional, up to 10, whole movies or series only), in your order. A pin can come from any library. A pin whose title has gone, or whose video file can't be found, is skipped and shown as "missing".
2. The rest go to the most watched titles over the last 7 full UK days before the run day (for the Sunday run: last Sunday to Saturday). The score is "viewer-days": each person who watched a title on a given day adds 1, however much they watched that day. Episodes count towards their series.
3. Ties: the title with the newest added content wins, then the newer premiere date, then the lower Emby ID number.
4. If fewer than 10 titles were watched, the gaps are filled with the most recently added titles.
5. Only movies and series from the libraries you choose (default: all movie and TV libraries except Top Picks). If there are fewer than 10 possible titles, the row is just shorter.

**What "watched" means.** For a person on a day: Emby marked it as played, or they watched at least half its length that day (two sittings add up), or at least 20 minutes if the length is unknown. For series this is per episode: bits of different episodes don't add up.

**What it does to files.** For each pick it makes a "copy" in the Top Picks folder (`...\programdata\data\top-picks`): a folder named `Title (Year)` holding small text files (`.strm`, each just the path to the real video so Emby plays the real file), information files (`.nfo`, holding title, plot, age rating and so on), subtitles, the backdrop, the logo, the theme video/song (first week only), episode thumbnails and season posters, and the numbered picture (`folder.png`/`thumb.png`, 1000×562: backdrop, black shading on the left, big white number, logo bottom-left of the picture, or the title in white text if there is no logo). Everything is built first in a private "staging" folder Emby can't see, then:
- copies of titles that drop out are deleted;
- copies of titles that stay are updated file by file in the same folder (so your watched tick on them stays);
- new copies are moved in.
It keeps its own list ("managed list") of the folders and files it made, and it only ever deletes things on that list, after safety checks (no odd names, nothing outside the Top Picks folder, never following shortcuts/junctions). Anything else in the Top Picks folder is never touched.

**How the order is kept.** Emby's "Latest" row shows the newest "date added" first. After moving files in, the plugin asks Emby to rescan only the Top Picks library, waits (up to 15 minutes, 30 for very long series), then sets each copy's "date added" directly in Emby: pick 1 = the run's start time, pick 2 = one hour earlier, and so on (for a series, the series and every episode get the same date). The same date is written into the `.nfo` so a later refresh agrees. It redraws the pictures, re-checks the dates, then looks at the row the way a normal (non-administrator) user sees it and checks it is right; if not, it sets dates again once and re-checks. Between runs, an "order guard" re-checks the dates after every library scan and 2 minutes after Emby starts, and puts back any that have changed. If Emby restarts mid-run, the run carries on where it stopped with the same picks; if a run errors while Emby is up it retries after 5 minutes (4 tries in all), then gives up and is marked failed.

**Plays and watched.** The plugin keeps its own record of who watched what (user, title, day, minutes, whether marked played) for 90 days, stored only on the server and shown only to administrators. A play on a Top Picks copy counts for the real title. On the first run it imports the previous 7 days once from the Playback Reporting plugin's history (or, if that can't be read, from each user's "last played" dates). When someone finishes or part-watches a copy, the real movie/episode is marked played or gets the same resume point; marking a copy watched/unwatched by hand is copied too; new copies start with each user's watched ticks from the real title.

**Settings page and report** (administrators only): choose libraries; choose the "row-check user" (blank = first non-admin user without restrictions); add, reorder and remove pins; Run now with a "running" indicator; and the last run's report: when it ran, finished/incomplete/failed, each title's rank and why (pinned / X viewer-days / filler), whether its copy and date worked, the row check result, plays in the last 7 days, missing pins, failed pictures, the last refused run and why, and the plugin and Emby versions.

**Taking over from the old plugin.** On the first run, folders already in the Top Picks folder that contain at least one `.strm` and one `.nfo` (including in subfolders) are treated as the old plugin's, added to the managed list and linked to their real title through the path in their `.strm`. They are never updated: the ones no longer picked are deleted, ones still picked are replaced by a fresh copy. Anything else is left alone forever. Your old pins are re-entered by hand. If the old plugin is still installed, Top Picks Plus does nothing at all (no runs, no play logging) and the report tells you to uninstall it.

**When things go wrong.** Runs refuse (and record why) if: a run is already going, the old plugin is loaded, no library uses the Top Picks folder, that library's .nfo reader is off or an .nfo saver is on, the managed list can't be read, or a data file was written by a newer version. A damaged play log or run record is renamed and started fresh. If drawing a picture fails, the plain backdrop is used and the report says so.

**Build order and go-live.** Five pieces, each built on its own branch, checked by the build robot (GitHub Actions) and reviewed by a fresh agent: (1) the rules (choosing, counting, naming, dates, plans) plus build tooling; (2) file handling (data files, staging, swap, deletes, takeover files); (3) the pictures, with three samples for you to approve; (4) everything that talks to Emby; (5) the settings page and report. Nothing goes on your server until all five are done. Then one release, v1.0.0. Go-live day: uninstall the old plugin, install v1.0.0, restart Emby, press Run now, then go through the checks. To undo that day: uninstall Top Picks Plus and reinstall the old plugin from the Desktop backup.
