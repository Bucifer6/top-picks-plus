## How the automatic tests work (D18, D31)
- **Test layer** says where the automatic test lives: **L** = Logic (plain records in, answer out, xUnit, with Stryker mutation testing in CI; the build fails below 80% of mutants caught); **S** = Store, with real files in a temporary folder on Windows; **R** = Run, with real files in a temporary folder and fake EmbyBridge adapters (in-memory lists of items, users, libraries, dates and played state) and a fake clock and time zone; **B** = EmbyBridge, its task, timers, listeners and API service run against fakes of Emby's own service interfaces made with NSubstitute (D47) and a fake `IBridgeClock`; NSubstitute and Mono.Cecil are added to the test project by the first EmbyBridge build chunk; **W** = wall tests in BoundaryTests.cs, reading the built DLL's types by reflection, and C49's scan reading its method bodies with Mono.Cecil; **Art** = Artwork, drawing real PNGs with SkiaSharp at the version Emby loads (read from the server first, D15) and checking pixels at fixed points.
- An A check's automatic test proves the rule; the owner's check proves Emby really behaves that way. A check with no Auto mark is the owner's only, because it needs the real server (it needs Emby's real behaviour; EmbyBridge's own code is tested against fakes in layer B).
- Junctions in tests are made with `cmd /c mklink /J` and file symbolic links with `File.CreateSymbolicLink` (the build machine runs with the rights to make them) on the Windows build machine; Run's and Store's link checks (C27, C50, C52, C76) are tested against real junctions, never only against fakes. Run's lock (C22, C56) is tested by starting 10 runs at once through the start-run hook and checking exactly one goes ahead.
- Every test that covers a check is tagged with its check ID (`[Trait("Check", "C10")]`); the tag is what counts, and test names may also start with the ID. A meta-test fails the build if any check marked A or T has no test tagged with its ID, once its feature is built: it reads this table and `tests/TopPicksPlus.Tests/built-features.txt` (one feature ID per line, added to in the same pull request that builds the feature, so it can't pass by skipping a check). Both the meta-test and built-features.txt are created in the first build chunk (Stage 6); they don't exist yet. Results are reported per check and none is forgotten.
- The test project will reference SkiaSharp (with its Windows native files, tests only, never shipped) at the version Emby loads, added by the first Artwork build chunk, for the Art layer and so the boundary check can load Artwork's types.
